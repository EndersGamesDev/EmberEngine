# Fire Racer V2 simulation handoff

All work is isolated to Fire. The core owns vehicle motion and authoritative race rules; renderer/UI and network changes are separate workers' files. The explicit draft is in `fire-racer-v2.md`.

Three chassis now have actual acceleration, terminal speed, braking, grip, steering and mass differences: GT (45 m/s, 1350 kg), Apex (43 m/s, 1040 kg) and Muscle (49 m/s, 1620 kg). Keyboard steering builds smoothly and returns faster. Reverse motion no longer invokes the forward-only spin limiter. Sustained road slides earn a single mini boost on release; stationary handbrake cannot earn charge.

Four rows of three mystery boxes refill empty item slots and respawn after five seconds. The draw is an integer hash of the race tick, box and driver, with more Nitro and Pulse opportunities for trailing positions. No random state advances per frame. Items are Nitro (2.5 s), Shield (7 s or one attack), guided Pulse (5 s lifetime, 66 m/s), Oil (9 s patch, 1.7 s grip loss), and Grip (6 s with oil immunity). Shields resolve before attacks within the same tick. Impacts reduce speed once and protect against chains for 2.5 s; steering remains available. Pulse is retained if no unfinished driver is ahead in standings.

Contacts use a pair of discs along each chassis, three ordered separation passes, mass-weighted impulses and low restitution. This is a stable, inexpensive approximation to rigid vehicle contact; it is not a tyre or suspension simulator. Finished cars follow the road and brake gradually, and no longer obstruct unfinished competitors. A three-second stall/backward check recovers drivers to the nearest centreline point without changing checkpoint or lap progress. Manual recovery uses the same helper.

Wire-relevant car fields are `vehicle`, `item`, `steer_angle`, `shield_left`, `grip_left`, `hit_left`, `oil_left`, `drift_charge` and exact `boost_left`. Client prediction steps these motion/effect fields only; the race owns item collection, projectile and slick attacks. Public `Race.pickups`, `Race.projectiles` and `Race.hazards` provide world visuals. `Race.elapsed` advances only while racing; `Racer.finish_time` freezes each driver's actual race duration.

Verified: the initial native `cargo test -p fire-core` build ran at Idle priority in 21.1 seconds and exposed a post-finish coast running off the road. After road-following braking was added, all 60 tests passed in 4.2 seconds, including an eight-driver three-lap completion/replay test; item consumption and counterplay; pickup refill; collision momentum; recovery progress; smooth/reverse steering; drift charge; and existing circuit checks. The replay check compares two runs on this host, not cross-platform replay equivalence. Initial core Clippy took 2.6 seconds and found only two test assertion-style issues, subsequently fixed. Final integrated verification belongs to the parent worker.

Reviewed by reading after the first green gate: same-tick defensive ordering, fixed driver/box collision ordering, Pulse targeting, progress preservation and prediction status coverage. Review caught expired attacks remaining eligible on their final simulation tick; the code now discards them before hit registration, with a focused regression test alongside same-tick Shield protection. That added test is pending the parent's integrated gate at this handoff.
