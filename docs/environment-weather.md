# Outdoor environment and weather

Arena v22 uses the shared engine's `Frame.environment` for a visible directional sun, moving procedural clouds and a directional shadow pass. `Frame.particles` carries camera-facing transparent particles. Other games retain their existing lighting through `Environment::default()`; `Environment::outdoor(Weather::Clear, time)` opts a scene into the outdoor renderer.

The sunlight direction is a vector toward the light. The sky disc, mesh lighting, specular highlights and shadow projection all consume that one direction. Freight Yard uses warm afternoon light; Trench City has denser cloud and passing rain. Weather follows the client's presentation clock and never affects authoritative movement, hit registration, map generation or the simulation RNG. Protocol 17 remains unchanged.

Rain has a fixed upper limit of 320 particles before shelter filtering, with analytic positions rather than accumulated per-frame spawning. The arena removes drops whose bottom crosses the floor or falls beneath the top of an obstacle, including raised tunnel roofs. Cloud cover and rain intensity vary slowly. Native captures can set `EMBER_WEATHER=clear`, `cloudy` or `rain` to pin the weather preset. The map selects the browser preset.

Instances cast and receive shadows by default. Viewmodel geometry, crosshairs and transient effects use `without_shadow()` so a first-person weapon or a hit marker cannot cast an enormous shadow across the level. Floors and selected props opt into wetness with `with_wetness()`. Wetness produces view-dependent reflections of the procedural sky and sun; it is not a reflection of nearby characters or scene geometry. Opaque material texture handling is unchanged.

The renderer uses ordinary raster passes and uniform buffers on the existing WebGL2 floor. Weather requires no compute shaders, storage buffers, downloaded textures or additional GPU features. The directional shadow map is a 1536-square RGBA8 packed-depth target with a separate depth attachment and 3-by-3 comparison filter. Its camera-centred projection is snapped to texels; it is not a cascaded or ray-traced shadow system. The sky and particles are rendered into the scene image, before the existing presenter. Particle quads are sorted back to front, alpha blended and depth tested without writing depth, with a hard renderer cap of 4096 valid particles. Arena smoke uses this channel with fading alpha, preserving the existing muzzle-flash delay and lifetime; sparks and debris remain solid meshes.

## Verification and capture

Run the engine's renderer/environment tests and the arena's weather tests, then the full engine/arena/game test suites. Native shader validation must execute the GPU pipelines; compiling Rust alone cannot validate WGSL. Build all four published game wasm bundles and the Julibrot lab bundle required by the publishing script. Use the existing script-driven capture harness for both `freight-yard` and `trench-city`, checking sunlight, cast shadows, cloud movement, wet cobbles and rain under cover. `EMBER_SCRIPT` keeps the capture independent of the operator's keyboard and mouse.

The headless release gate is `cargo test -p ember-engine environment_gpu -- --ignored`; set `EMBER_ENV_CAPTURE_DIR` to an existing directory to retain its seven diagnostic PNGs. It executes the shipping raster pipelines at WebGL2 limits and checks shadow changes, sky/sun visibility, moving clouds, wetness opt-in, particle depth occlusion and order-independent input sorting. `tools/v22/browser-environment-smoke.cjs` runs both real shooter maps through WebGL2 in isolated headless Chromium, without any keyboard or mouse events. Point `EMBER_QA_PLAYWRIGHT` at an installed Playwright module; the script documents optional browser/server paths, reserves test-only loopback ports, and writes captures/report beneath ignored `target/environment-captures`.

Verified on 2026-09-04: 482 tests across engine, arena, arena-core, arena-server, fire, kings and editor passed in an isolated native build, including network integration and doc-test gates; the explicit GPU pixel gate passed separately (0.19 s warm execution). Clippy passed for the same crates and all targets (17.41 s isolated check). Five release wasm bundles built and generated bindings successfully. The actual Freight Yard and Trench City browser runs used WebGL2 through ANGLE on Intel UHD 770, joined protocol 17 and continued drawing without browser errors or warnings (12.04 s initial two-map run). Screenshots of both maps and native shadow/cloud/reflection checks were visually inspected. These are correctness checks, not an AAA-quality or device-performance certification; no frame-rate target is claimed.

Future extensions include physically authored roughness/metallic materials, scene-geometry reflections, cascaded shadows, volumetric clouds and weather audio. These require their own visual and performance evidence; none is implied by the v22 environment reflection or cloud layer.
