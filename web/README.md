# Web site

This directory is the source tree for ember's GitHub Pages site: the launcher, developer landing page, shared host selection, game catalogue, versioned game pages and browser labs.

Players depend on `index.html` and `games.json` for the active-lobby showcase, browser-local generated handles, version picker and one wasm bundle for the selected game or lab; lobby listing happens before any game bundle loads. Each live page depends on `deploy/deploy-pages.sh` to assemble its matching generated bindings and wasm binary.

`loader.ts.j2` is the checked page-side source of the emitted root `loader.js` and the one call a live page makes instead of importing its own bundle. It starts host discovery and the bundle download in the same tick — the preliminary protocol comes from the page's own `games.json` entry, so the host chip can settle before the whole download — then exposes the bundle's `proto_version()` as the authoritative result once initialisation finishes and retries an empty or disproved ranking after the link is idle. With working loader rules the page consumes that retry's host event without holding practice mode behind a second probe window; when the rules are unavailable there is no event channel, so the degraded path waits and returns the retry directly. Download progress starts from an unencoded `Content-Length` without waiting for the catalog, upgrades to the catalog's decoded bundle size if it arrives while the download is open, gives the catalog four seconds before proceeding without it, discards any total the decoded body outruns, and reports the compile, initialisation and game start as events the page renders in its existing line or bar. This distinction is active in production: Arena v31 is served with gzip `Content-Length` 34,402,374 while its decoded bundle is 44,337,809 bytes. The rules those events follow live in [`../crates/ember-loader`](../crates/ember-loader); the template is the browser input and output they describe.

Three properties are worth knowing before changing a page. The loader stamps every URL it builds from the `?v=` on the page's own import of it, which the deploy rewrites, so a page and the bundle it loads always come from one build. The stamp is not template context: `loaderStamp` reads it at run time from `import.meta.url`. Discovery and the download are separate tracks, and the host track has an explicit re-rank transition that may settle after ready, so an early miss can be retried without producing out-of-order failures while a page with no server still loads its game and says so. `hostSettled` resolves to `{ host, candidates, wrongProto, proto, book }`, the same host view returned at top level after the safety pass; the ordinary path leaves that promise in the background, while the degraded path has already awaited it. If the loader's own bundle cannot be loaded, `loader.js` falls back to the path every page used before it existed — import the glue, let the browser fetch the bundle — so the page still plays, with one honest line in place of progress numbers. `loader.test.mts.j2` pins the browser-side ordering, retry, byte counting and failure phases as an independent checked template; its emitted suite runs against the emitted browser modules. Its generated-loader cases are skipped before assembly and run after the real loader wasm and bindings exist, while the phase transition is always covered natively by the crate tests. Generated and wasm-bindgen declarations are compiler inputs under `target/web-generated`; none is published to players.

The event object has these properties: `phase`, `status`, `elapsedMs`, `phaseMs`, `loaded`, `total`, `percent`, `rateBps`, `etaMs`, `stalled`, `stalledMs`, `reason`, `detail`, `text`. The loader omits an optional property when that measurement or failure field does not apply; it does not publish the property with a null value, so pages may test absence with `in`, optional access or a nullish comparison. Host events add `host`, `candidates`, `wrongProto`, `proto` and `provisional` under their own rule: `host` and `proto` are null when absent, the two lists are always arrays, and `provisional` is always a boolean.

The complete phase adds only these four runtime boundary guards; no other previously accepted input is narrowed. A Node command using the pinned TypeScript compiler API selects each emitted top-level `FunctionDeclaration` from `getStart` through its following LF: raw cost is that span's UTF-8 byte length, and gzip cost is the full emitted module's `gzip -9 -n -c` size minus the same invocation after deleting exactly that span.

|Guard|Boundary action|Raw bytes|Gzip bytes|
|-----|---------------|--------:|---------:|
|`eventFrom`|Drops an out-of-contract loader event before a page handler sees it.|843|161|
|`loaderRulesFrom`|Rejects an imported loader namespace without a callable `Loader`, or with a non-callable default export.|670|86|
|`gameGlueFrom`|Rejects imported game glue without a callable default export.|343|26|
|`hostsModuleFrom`|Rejects an emitted host-gate dependency missing one of its required callable exports.|595|143|

`hosts.ts.j2` and `loader.ts.j2` compile under `tsconfig.web.json` into `target/web-generated/js`. The assembler copies only `hosts.js` and `loader.js` by name to the Pages root; the exhaustive-consumer stub emitted by the same project remains unshipped. Their suites compile from `hosts.test.mts.j2` and `loader.test.mts.j2` under the Node project and are run by explicit emitted path. The publication contract lives in [`deploy/deploy-pages.sh`](../deploy/deploy-pages.sh), host discovery lives in [`docs/hosts.md`](../docs/hosts.md), and version selection, frozen pages and release tags are governed by [`docs/versioning.md`](../docs/versioning.md).
