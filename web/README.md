# Web site

This directory is the source tree for ember's GitHub Pages site: the launcher, developer landing page, shared host selection, game catalogue, versioned game pages and browser labs.

Players depend on `index.html` and `games.json` for the active-lobby showcase, browser-local generated handles, version picker and one wasm bundle for the selected game or lab; lobby listing happens before any game bundle loads. Each live page depends on `deploy/deploy-pages.sh` to assemble its matching generated bindings and wasm binary.

`loader.js` is the page-side half of the shared loader and the one call a live page makes instead of importing its own bundle. It starts host discovery and the bundle download in the same tick — the preliminary protocol comes from the page's own `games.json` entry, so the host chip can settle before the whole download — then exposes the bundle's `proto_version()` as the authoritative result once initialisation finishes and retries an empty or disproved ranking after the link is idle. With working loader rules the page consumes that retry's host event without holding practice mode behind a second probe window; when the rules are unavailable there is no event channel, so the degraded path waits and returns the retry directly. Download progress starts from an unencoded `Content-Length` without waiting for the catalog, upgrades to the catalog's decoded bundle size if it arrives while the download is open, gives the catalog four seconds before proceeding without it, discards any total the decoded body outruns, and reports the compile, initialisation and game start as events the page renders in its existing line or bar. This distinction is active in production: Arena v31 is served with gzip `Content-Length` 34,402,374 while its decoded bundle is 44,337,809 bytes. The rules those events follow live in [`../crates/ember-loader`](../crates/ember-loader); this file is the browser input and output they describe.

Three properties are worth knowing before changing a page. The loader stamps every URL it builds from the `?v=` on the page's own import of it, which the deploy rewrites, so a page and the bundle it loads always come from one build. Discovery and the download are separate tracks, and the host track has an explicit re-rank transition that may settle after ready, so an early miss can be retried without producing out-of-order failures while a page with no server still loads its game and says so. `hostSettled` resolves to `{ host, candidates, wrongProto, proto, book }`, the same host view returned at top level after the safety pass; the ordinary path leaves that promise in the background, while the degraded path has already awaited it. If the loader's own bundle cannot be loaded, `loader.js` falls back to the path every page used before it existed — import the glue, let the browser fetch the bundle — so the page still plays, with one honest line in place of progress numbers. [`loader.test.mjs`](loader.test.mjs) pins the browser-side ordering, retry, byte counting and failure phases; its generated-loader cases are skipped in a clean source tree and run only after `cargo build --target wasm32-unknown-unknown --release -p ember-loader --lib` and `wasm-bindgen --target web --out-dir web/pkg target/wasm32-unknown-unknown/release/ember_loader.wasm` place the generated loader in `web/pkg`, while the phase transition is always covered natively by the crate tests. The generated declarations from that command are compiler inputs staged under `target/web-generated`; no generated declaration is published to players in phase 0.

The event object has these properties: `phase`, `status`, `elapsedMs`, `phaseMs`, `loaded`, `total`, `percent`, `rateBps`, `etaMs`, `stalled`, `stalledMs`, `reason`, `detail`, `text`. The loader omits an optional property when that measurement or failure field does not apply; it does not publish the property with a null value, so pages may test absence with `in`, optional access or a nullish comparison. Host events add `host`, `candidates`, `wrongProto`, `proto` and `provisional` under their own rule: `host` and `proto` are null when absent, the two lists are always arrays, and `provisional` is always a boolean.

The complete phase adds only these four runtime boundary guards; no other previously accepted input is narrowed.

|Guard|Boundary action|
|-----|---------------|
|`eventFrom`|Drops an out-of-contract loader event before a page handler sees it.|
|`loaderRulesFrom`|Rejects an imported loader namespace without a callable `Loader`, or with a non-callable default export.|
|`gameGlueFrom`|Rejects imported game glue without a callable default export.|
|`hostsModuleFrom`|Rejects an emitted host-gate dependency missing one of its required callable exports.|

The publication contract lives in [`deploy/deploy-pages.sh`](../deploy/deploy-pages.sh), host discovery lives in [`docs/hosts.md`](../docs/hosts.md), and version selection, frozen pages and release tags are governed by [`docs/versioning.md`](../docs/versioning.md).
