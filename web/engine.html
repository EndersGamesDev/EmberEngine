a from-scratch game engine

ember

Rust and wgpu, one wasm bundle. A deterministic engine whose games run in a browser tab and on the desktop from the same code — no install, no CDN, no backend for the player.

● the four pillars

engine = compiler + small runtime

Baked, not parsed

Assets — glTF, textures, shaders — are compiled offline into flat, memory-mappable blobs. The shipped runtime maps, uploads, runs; it never parses at startup, and the web bundle carries every byte at compile time.

gpu-driven rendering

The CPU hands over a camera

Bindless resources, culling in compute, indirect draws, a small render graph — the direction of travel. Today the scene pass is deliberately small and documented, and the constraints it lives under are the design.

deterministic simulation

60 Hz, seeded, fixed order

Fixed timestep, seeded RNG (two world-generation LCGs and nothing else), fixed update order. Replays, save states and rollback netcode fall out of it for free; the client predicts and the server is authoritative.

iteration speed is a feature

Blender edits, the engine inspects

Hot-reloadable shaders, an in-engine overlay, time-travel debugging on top of the deterministic sim. Blender is the content editor; the engine is where the running game is inspected.

● the shape of it

game

arena, fire, kings — each with its own server and its own protocol number

scene / simulation

the deterministic 60 Hz sims, shared by prediction and authority

renderer

owns wgpu; the scene pass, the presenter, the GPU heap

platform

winit window, events, input — the only layer that touches the OS

Strict one-way layering: nothing reaches back up, and nothing above the renderer touches the GPU. A change in a shared sim crate is a protocol question until it is proved not to be — that single rule is what keeps a client and a server playing the same game.

● the web story

One bundle, no runtime fetch

Each game is a single wasm file with every asset baked in at compile time. The page is the download; the deploy is a static host. The cost is measured in megabytes and tracked in the backlog.

A documented floor

WebGL2 plus one extension — no WebGPU, no cross-origin isolation. The exact floor, and the real devices it excludes, are written down in docs/minimum-requirements.md. A device below it gets a typed refusal, never a blank canvas.

An address book, not a central server

Any machine can host a game behind a tunnel. The page fetches the book, asks every host in one round trip, and picks the newest build that speaks its protocol — the emptiest among those, the nearest among those. Old versions stay playable on old hosts. The full model is docs/hosts.md.

● determinism, for free

Fixed 60 Hz, two seeded LCGs, fixed update order. The client predicts its own movement against the same sim the authoritative server steps, and reconciles against 30 Hz server state. Bullets are stepped server-side only — the sole reason hit registration can use ordinary floats.

So: replays, save states, rollback netcode, and reproducible bugs. If a replay diverges, the divergence is a bug with an address, not a mystery.

● honest state

Young, pre-1.0, one developer, AI-assisted. The games ship; the engine is still earning its keep. Public roadmap, in the README: physics (rapier) is the next sim addition; an offline asset compiler and the GPU-driven rendering pass are the next big two; shadow mapping is still open.

The backlog is one line per known gap — docs/plans/backlog.md — several of them small enough to be a first pull request. CONTRIBUTING.md is the short version of the rules; CLAUDE.md the long one.
