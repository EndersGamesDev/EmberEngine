# Deployment

This directory holds the scripts that build the Pages release asset, start or ship game hosts, maintain the multi-host address book, stamp releases and operate host watchdogs and timers.

The live launcher and game servers depend on these scripts for reproducible bundles, protocol-aware addresses and process ownership across Linux, Windows and WSL hosts.

Changes integrate through pull requests to `develop`; validated release tags advance the live `main` branch so Pages and hosts select the same source. The full branch and promotion contract lives in [`docs/branching.md`](../docs/branching.md).

Use [`retag.sh`](retag.sh) for the completed historical tag migration and [`github-releases.sh`](github-releases.sh) to derive GitHub Releases from those tags and `CHANGELOG.md`.

[`check-hosts.mts.j2`](check-hosts.mts.j2) is the checked source of the emitted host gate: does every live server game in a catalog have a host it can actually join? It loads an address book, fetches its bound mirrors, merges and ranks with the emitted `hosts.js`, probes every host that runs the game and only then applies the protocol filter, so a live `Welcome` outranks a book that has gone stale. A host that stays silent is asked again — three attempts at most, the second after a pause of 1 s and the third after a further 2 s — so that a blip shorter than a probe cannot fail a deploy of a site whose hosts are working, while a host that answers on another protocol is taken at its word the first time; the reported line names the attempt that carried a host and, where none did, what every attempt reported. `--hosts-js <path>` still wins over every fallback, `--tree <dir>` resolves `<dir>/hosts.js`, and a local book resolves `hosts.js` beside it; the final development fallback is the emitted sibling `../js/hosts.js`. Its unit and command-line tests are the independent `check-hosts.test.mts.j2` template, compiled and run by explicit emitted path under `node --test`.

[`deploy-pages.sh`](deploy-pages.sh) resolves its wasm inputs beneath `${CARGO_TARGET_DIR:-target}`, builds the shared loader (`ember-loader`) beside the six game bundles, renders the checked web templates and emits them with `tsconfig.web.json`. It copies only `target/web-generated/js/hosts.js` and `target/web-generated/js/loader.js` by name to the Pages root; it neither copies the output directory nor publishes the exhaustive-consumer stub. The source-copy pass refuses tracked `web/hosts.js`, `web/loader.js` or a bare TypeScript source beside their templates. It derives the remaining root and live-page files from Git's tracked runtime trees, excluding repository README files, root tests and mirror input, generated `pkg` directories, TypeScript templates and source version sidecars; generated bundles and assembly-owned version sidecars are added separately, and League v4 also derives the tracked v2 art tree its page references. That copy owns the archived v2 directory's art until v4 carries its own. Arena v0 is not a live source tree: its directory stays byte-for-byte as the publication seed supplied it.

Before it copies tracked page sources, the assembler keeps wasm-bindgen declarations under the SHA-scoped `target/web-generated` tree, runs `ember-webgen`, refreshes the fixed browser and Node compiler-input trees and invokes the repository-pinned TypeScript compiler. Compiler diagnostics pass through the generated line-map printer, which keeps rendered coordinates and adds the tracked template path and line. Generated declarations are mandatory inputs to the behavior templates, but neither those declarations nor wasm-bindgen declarations enter the Pages tree or archive. Install the exact JavaScript toolchain with `npm ci`; deployment never performs a network install.

`stage-wasm-types.sh` owns the append-only list of converted games whose wasm-bindgen declarations are required by typed browser templates, builds those wasm crates and stages their declarations identically for CI, the required TypeScript gate and Pages assembly.

The source-AST gate scans every rendered production source. Its wasm-declaration rule is currently exercised by a synthetic fixture: no rendered production source has a literal relative import resolving through a `wasm` path because the wasm-bindgen glue modules are imported by computed URL.

The Pages job does not take a gate sidecar from the release archive. After extracting the site it checks out the release source, selects Node 24.20.0, runs `npm ci`, selects the pinned Rust toolchain, regenerates the compiler inputs, emits `target/web-generated/node-js/check-hosts.mjs` and runs that tool against the extracted tree. The gate is a tool rather than a shipped byte, its provenance is the checked-out source like the `typed web` CI job, and the release archive remains exactly the site. Its rebuild is the same order as that CI job, about two minutes measured on 2026-09-14; a sidecar would still need extraction and removal before upload, and each later gate would repeat that packaging path. There is no release-workflow post-assembly host gate; Pages owns this live network check.

The assembler rewrites each live page's single `loader.js?v=` cache token to the deploy stamp and checks relative static imports, dynamic imports, direct worker entries and local runtime assets from every HTML, JavaScript and module-JavaScript file at the Pages root and in each named live tree, refusing a reference this assembly did not place before it writes an archive. One shared loader copy serves every page because its page-side half resolves both `hosts.js` and its own bundle relative to itself. After copying the six live game bundles, the deploy writes each decoded `_bg.wasm` size as `bytes` beside that release's `proto` in the assembled `games.json`; the tracked catalog has no generated sizes. The loader prefers this decoded total, uses `Content-Length` only when no `Content-Encoding` is present and leaves the total unknown otherwise.

The derived Julibrot stamp list covers every top-level `.html` and `.js` file and fails closed if any lacks a `?v=1` token; the derived copy rule now also publishes the unlinked `whole-grid-oracle.html`, `whole-grid-v1.json` and `whole-grid-v1.rgba.deflate.bin`, about 145 KB in total, so exposing those proof files is deliberate rather than an accidental consequence of replacing the hand-maintained list.

[`../web/mirrors.json`](../web/mirrors.json) is the tracked list of mirror bindings that [`deploy-pages.sh`](deploy-pages.sh) merges into the assembled book, so a binding reaches players through the release rather than through the `hosts/book` branch, and [`republish-host.sh --per-host`](republish-host.sh) writes each host's mirror as `<host name>.json` so that one branch carries them all. [`ship-host.sh`](ship-host.sh) takes `EMBER_SHIP_REF` to build and stamp a named ref instead of the published commit, which is how a release puts its hosts in place before the tag is pushed.

Start with [`docs/hosts.md`](../docs/hosts.md) for the host model, use [`README-watchdog.md`](README-watchdog.md) for watchdog operation, and preserve the operational and verification constraints in [`CLAUDE.md`](../CLAUDE.md); shell behavior is pinned under [`tests/`](tests/).
