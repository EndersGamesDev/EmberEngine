# Arena v29 verification and scoped publication

These scripts do not build code or drive the operating system's input. Run Node at Idle priority. Browser QA launches one disposable headless browser and one owned loopback server; do not run it alongside another browser/GPU test. Network QA never starts or stops a server and touches only its own random-password private rooms. Public release proof sends read-only Hello packets, not gameplay input.

## Gates

- `node --experimental-vm-modules tools/v29/settings.test.cjs`: pure settings, storage-denied startup and page syntax. No browser.
- `node tools/v29/browser-parkour.cjs`: actual v29 page and built WASM, protocol22, WebGL2, settings/fullscreen state, remapping, input-pause leakage, saved preferences and authoritative parkour wire state. Set `EMBER_QA_PLAYWRIGHT` to the installed Playwright module; optional `EMBER_QA_BROWSER`, `EMBER_QA_SERVER`, `EMBER_QA_OUTPUT`. Ports8088 and7788 must be free; the script refuses to touch existing listeners. Default output is `target/parkour-browser`. Fullscreen/pointer-lock/focus methods are intentionally stubbed; this does not certify trusted browser permission behavior. This gate alone does not prove wall-kick gameplay.
- `node tools/v29/network-parkour.cjs ws://127.0.0.1:7788`: eight actual connected peers in each of FFA/TDM/Hill, 4v4 spawns/rejoin, ninth-player and old-protocol21 rejection, walk4/crouch2.2/sprint6.4, ADS/spread/shot recovery, then a ground slide, a descending wall slide and alternating physical-wall kicks in the positive-z Harbor service lane. All seven other peers must receive the actor's slide/kick state. Default output is `target/parkour-network`. This is a bounded functional test, not load/performance or exhaustive combat certification. Target a separately started disposable server first; run against a public host only with release-coordinator authorization. Public tunnel latency can invalidate the authored reactive wall-kick input timing and must not be silently treated as a physics defect.

The network route is authored input only: spawn0[-37,42] exits through[-37,45.4],[-31,45.4]; established movement checks finish at[-31,32], then the parkour approach is[-26,32],[-26,26.2],[-26,21]. At z21, the actual warehouse/office faces are x=-28/-24, both4.2m high, with player-contact centers near-27.4/-24.6. The roof bridge is farther inward at z16.6..18.8, outside this fixture. Optional `EMBER_QA_APPROACH`, `EMBER_QA_DIRECTION`, `EMBER_QA_ROUTE`, and `EMBER_QA_PARKOUR_APPROACH` JSON inputs can replace authored waypoints; they do not override positions, geometry, state or physics. Default routes must be executed against the final build before claiming success.

## Arena-only publisher

`node tools/v29/publish-arena.cjs --build-commit=<full-clean-source-SHA> --wasm-sha256=<tested-WASM-SHA256>` prepares only. Record those two values during the clean build and QA; the publisher verifies their equality to the current source and artifact, but cannot reconstruct compiler provenance. Required source inputs are `web/pkg/arena.js`, `arena_bg.wasm`, the v29 page/settings, and the new Arena catalog entry. The clean commit must already equal fresh `origin/main`. It also requires the published address book to have protocol22 at top level and select an actual protocol22 server built from that source revision. It does not edit `server.json`; coordinate the server-first/address-book transition separately.

The publisher fetches fresh Pages, initializes a sparse detached worktree's complete index with `read-tree -mu HEAD`, and stages only seven paths: the four new Arena files, the Arena catalog replacement inside `games.json`, `version.json`, and one v28→v29 Arena fallback replacement inside the existing root launcher. It never replaces the whole launcher from main, copies unrelated builds, or rebuilds Fire. Every peer catalog object, peer directory tree, frozen v28 tree and address book is checked unchanged. Every Git invocation forces `core.autocrlf=false`. The settings cache token is the first12 SHA256 hex characters. `web/version.json` is an ignored generated build stamp, not a source edit.

Inspect the reported temporary worktree and `target/parkour-publish/results.json`. Rerun the same command with explicit `--push` to freshly revalidate, commit and perform a normal non-force push. A concurrent Pages update aborts; rerun against the new tree, never force. Worktrees are retained for inspection; the tool does not recursively remove anything.

After Pages finishes, set `EMBER_QA_PRESERVED_PAGES` to the publisher's exact `base` commit and run `node tools/v29/public-release.cjs`. It checks the new Arena bytes/cache key, all peer catalog objects and live files, frozen v28 files, launcher single-change invariant, build stamp and read-only protocol22 Welcome. Default preservation baseline is3dc66e0a, but a concurrent peer update requires the actual new publication base. Default output is `target/parkour-public`.
