## Arena-only publisher

`node tools/v29/publish-arena.cjs --build-commit=<full-clean-source-SHA> --wasm-sha256=<tested-WASM-SHA256>` prepares only. Record those two values during the clean build and QA; the publisher verifies their equality to the current source and artifact, but cannot reconstruct compiler provenance. Required source inputs are `web/pkg/arena.js`, `arena_bg.wasm`, the v29 page/settings, and the new Arena catalog entry. The clean commit must already equal fresh `origin/main`. It requires an actual protocol-22 server from that exact revision/version, discovered through the current book or one of its existing bound mirrors. Live identity is checked before and after preparation; commit abbreviations must uniquely resolve to the exact source commit. Unavailable/invalid hosts are dropped independently.

The publisher fetches fresh Pages, initializes a sparse detached worktree's complete index with `read-tree -mu HEAD`, and stages only eight paths: the four new Arena files, the Arena catalog replacement inside `games.json`, `version.json`, one v28→v29 Arena fallback replacement inside the existing root launcher, and `server.json`. The book transition changes only the top-level Arena `proto`, `ws` and cache `v`, atomically with the new client. Every other book field and the entire hosts/mirrors lists stay unchanged. In particular, a mirror host is NEVER copied into hosts: the browser gives that list precedence, which would mask future tunnel rotations and the mirror's other games. The existing host-list writer retains sole ownership of entries. It never replaces the whole launcher from main, copies unrelated builds, or rebuilds Fire. Every peer catalog object, peer directory tree and frozen v28 tree is checked unchanged. Every Git invocation forces `core.autocrlf=false`. The settings cache token is the first12 SHA256 hex characters. `web/version.json` is an ignored generated build stamp, not a source edit.

Inspect the reported temporary worktree and `target/parkour-publish/results.json`. Rerun the same command with explicit `--push` to freshly revalidate, commit and perform a normal non-force push. A concurrent Pages update aborts; rerun against the new tree, never force. Worktrees are retained for inspection; the tool does not recursively remove anything.

After Pages finishes, run `node tools/v29/public-release.cjs`. It requires the successful publication report and automatically uses its exact `base` commit; optional `EMBER_QA_PRESERVED_PAGES` must equal that base. It checks the new Arena bytes/cache key, all peer catalog objects and live files, frozen v28 files, the three-key book transition, launcher single-change invariant, build stamp and read-only protocol22 Welcome. Default output is `target/parkour-public`.

## Approved rollout and updater repair

The user approved publishing and all three automatic Knecht restarts at the start of the release turn. Fresh observation then confirmed a pre-existing loop: after a successful oneshot tick, systemd's default control-group shutdown killed all six server/tunnel children it had just published. The scoped installer fix uses `KillMode=process` because `host.sh` already owns their PID/start-time lifecycle; stopping the timer is not stopping the games (`host.sh down` is). Both host-tick invocations close descriptor9 before calling host.sh, preventing retained children from holding the update lock forever. The isolated host-timer suite tests generated units and lock inheritance, with real Linux flock assertions in CI. Applying the fixed unit to Knecht and observing successful ticks with retained PIDs is required before claiming auto-update health. No Windows v28 restart is required if Knecht's bound mirror supplies the new compatible server.
