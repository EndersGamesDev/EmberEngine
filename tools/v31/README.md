# Killshot v31 · Breach-12 release gates

v31 adds the Breach-12 shotgun as weapon ID 8 and requires protocol 24. Its agreed weapon contract is eight deterministic pellets per shell, six shells loaded, 24 in reserve, a 0.85-second firing cycle and a 2.8-second reload. Slot 9 remains reserved. The JavaScript HUD displays authoritative ammo/reload state rather than duplicating gameplay stats. Existing v30's 22-action settings schema and `ember-killshot-settings-v1` key are unchanged, so sensitivity and all remaps, including a previously customized slot 8, load directly without a reset. The older pre-v30 migration remains supported.

## Pure gates

Run Node at Idle priority. `node --experimental-vm-modules tools/v31/settings.test.cjs` checks settings compatibility, legacy migration, all eight HUD weapon names, shotgun ammo/reload telemetry, inaccessible slot 9, safe HUD rendering, page syntax and startup storage failures. The initial 134 checks passed in 10.938 ms. `node --test tools/v31/release-book.test.cjs tools/v31/release-scope.test.cjs` passed all 10 pure publishing guards in 71.426 ms; those tests inject network/commit lookups and never contact a host. Those suites plus four operational-module syntax checks took 0.387 seconds combined at Idle.

`node --test tools/v31/shotgun-events.test.cjs` checks the shared network fixture's event validator, including IDs at the 52-bit boundary and rejection of missing, duplicated, wrong-owner, mixed-shell, nonfinite or out-of-range events. These two pure tests passed in 61.340 ms; with network-script syntax and PowerShell wrapper AST parsing, the gate took 0.192 seconds. This validates assertions, not actual projectile behavior.

## Actual client and server gates

Do not run these while another worker owns a build, browser/GPU or QA server gate. The root coordinator supplies the new protocol-24 build and serializes execution. No actual client/server run is claimed by the initial preparation of these tools.

`tools/v31/browser-killshot.cjs` uses the same `EMBER_QA_PLAYWRIGHT`, `EMBER_QA_BROWSER`, `EMBER_QA_SERVER` and `EMBER_QA_OUTPUT` variables as v30. It owns disposable loopback ports 8088 and 7788 and refuses preexisting services. `--shotgun-only` runs the focused custom-ID-8 match, actual LIFE/ammo and hotbar display, responsive HUD bounds at 390/1600 pixels, slot 1/8/9 and remapped slot-8 routing, real firing, authoritative reload progress, reserve conservation and screenshots. Without the flag it first runs the inherited controls, seven-weapon reload and passive-peer agreement suite. Browser actions are authored DOM events in a hidden headless browser; OS-facing focus, capture and fullscreen APIs are stubbed. Neither trusted permissions nor hardware-controller behavior is claimed. Default output is `target/killshot-v31-browser`.

`tools/v31/network-test.ps1` starts one hidden Idle child on QA port 7788, checks that the listener belongs to the retained child process, runs the network fixture and stops only that child. Never run it against or replace the live port-7780 server. `network-shotgun.cjs` accepts only `ws://127.0.0.1:7788`; it retains the three-mode/eight-peer/capacity/rejoin and authored harbor movement/parkour gates, then opens a separate private Custom-Breach-12 room. A real sky shot must spend one shell and deliver exactly eight unique projectile IDs and identical endpoint records to all eight peers. Slot 8→1→8 retains five shells and 24 reserve; the real reload ends with six shells and 23 reserve for every observer. The fixture does not claim controlled pellet hit balance or visual quality. Output is `target/killshot-v31-network`.

Projectile identity is `((tick & (2^40 - 1)) << 12) | (original_player_id << 4) | pellet_index`. Use integer division rather than JavaScript's 32-bit bitwise operators: `Math.floor(projectile_id / 16)` is the shared shell key, modulo 16 is pellet index 0–7, and `Math.floor(projectile_id / 4096)` recovers the low 40 tick bits. All values fit below `2^52`. The original owner is `Math.floor(projectile_id / 16) % 256`.

`tools/v31/browser-grips.cjs` is a separate rendering-only fixture with no game server: its synthetic socket drives the real client/assets in a hidden WebGL2 browser. Default weapon is 8; select view names with `EMBER_QA_VIEWS`. Besides the original first-person/front/side/crouch/aim-up/aim-down views, the shotgun adds `first-person-ads`, `first-person-reload-32`, `first-person-reload-53`, `first-person-reload-72` and `third-person-reload-53`. ADS uses authored DOM intent with capture/focus/fullscreen APIs stubbed; reload packets freeze the requested phase and the report records the real client's bounded interpolation. These pictures prove rendering only, not reload timing or damage. Set a separate `EMBER_QA_OUTPUT` when retaining multiple capture sets.

## Scoped publication · coordinator only

These are existing GitHub Pages release helpers, not a new hosting service. No helper creates tunnels, restarts services, changes `hosts`/`mirrors` entries or builds another game. Run operational publisher modules only after the required user authorization and successful game/CI gates; even preparation fetches refs, probes public Welcome messages and creates a retained temporary worktree.

`node tools/v31/publish-arena.cjs --build-commit=<full-clean-SHA> --wasm-sha256=<tested-SHA256>` prepares only. Supply the actual clean build provenance, not a newly guessed hash. HEAD must equal current main, the Arena package and catalog must identify release `31.0.0`, and a currently discovered server must answer protocol 24 from the exact revision and revision-count build stamp. Release major 31 selects the retained `v31` directory slot; the full version identifies the release. The Pages base must still have one live v30/protocol-23 Arena entry and one v30 root-launcher fallback. Only eight paths may change: root `index.html` (the single fallback plus semantic version presentation), `games.json` (three-grade fields for existing entries plus the Arena release), `version.json`, only legacy `ws`/`proto`/`v` in `server.json`, and four new `games/arena/v31/` files. All other peer catalog metadata, all v30/v29 trees and all peer game/lab trees must match the prior Pages state. The sparse index must preserve the complete base tree. The source tree and tested WASM must stay unchanged, and the remote Pages branch must not move during preparation. No force-push or recursive cleanup is used.

Review the prepared diff, then rerun the same command with `--push` only with release authorization; it freshly revalidates rather than publishing a stale prepared tree. The report is `target/killshot-v31-publish/results.json`. After GitHub Pages completes, `node tools/v31/public-release.cjs` performs read-only HTTP/Welcome checks against that exact release report and commit. It verifies v31 HTML/settings/WASM bytes, Breach-12/HUD/reload shell, sole live catalog entry, scoped address-book/fallback changes, frozen v30/v29 files and peer live files. Output is `target/killshot-v31-public/results.json`. This proves public bytes and server identity, not gameplay, automatic deployment repair, or graphics.
